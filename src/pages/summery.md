## ۱. چشم‌انداز کلی سیستم

**DANA** یک سیستم جامع مدیریت دانش است که به‌طور خاص برای سازمان‌های بزرگ، با تأکید بر ساختارهای نظامی، دانشی و پژوهشی طراحی شده است.  
هدف اصلی این سیستم، **ایجاد پل ارتباطی بین نیازهای دانشی سازمان و تولیدات دانشی موجود** و در نهایت **تبدیل شکاف‌های دانشی به پروژه‌های پژوهشی و عملیاتی** است.

---

## ۲. معماری کلی (لایه‌ها)

سیستم بر اساس معماری **لایه‌ای (Layered Architecture)** پیاده‌سازی شده است:

| لایه | شرح |
|------|------|
| **UI (React + Tailwind + Vite)** | رابط کاربری واکنش‌گرا با پشتیبانی از حالت تاریک و نمایش درختواره‌های پویا با D3.js |
| **State Management (Zustand)** | مدیریت حالت متمرکز (کاربر، تنظیمات، درختواره‌ها، دوره‌ها و ...) |
| **API Layer (Express.js)** | ارائه RESTful API برای تمام عملیات‌ها |
| **Business Logic (Server Routes)** | پیاده‌سازی تحلیل شکاف، مدیریت درختواره‌ها، نظام مسائل، خروجی‌ها و ... |
| **Data Layer (SQLite + Drizzle ORM)** | پایگاه داده با رویکرد ORM و پشتیبانی از تراکنش‌ها و ایندکس‌ها |

## ۳. موجودیت‌های اصلی سیستم (Entities)

| موجودیت | شرح |
|----------|------|
| **درختواره دانشی (Knowledge Tree)** | ساختار سلسله‌مراتبی از دانش‌ها با سطوح R → T → B → SB → L → Q |
| **گره (Node)** | هر عنصر درختواره با سطح مشخص و قابلیت اتصال به قالب‌ها و نمونه‌ها |
| **قالب (Template)** | تعریف نوع دانش (مثل سیاستی، راهبردی، پژوهشی) |
| **نمونه قالب (Template Instance)** | نمونه واقعی از یک قالب (مثل یک سند یا گزارش خاص) |
| **دارایی دانشی (Knowledge Asset)** | مستندات، فایل‌ها و خروجی‌های متصل به گره‌ها |
| **شکاف دانشی (Gap)** | اختلاف بین درختواره مورد نیاز و تولیدشده |
| **آیتم پژوهشی (Research Item)** | موضوع پژوهشی که برای پر کردن یک گپ تعریف می‌شود |
| **مسئله (Issue)** | پروژه عملیاتی با بودجه، زمان‌بندی، تیم اجرایی و مراحل پیشرفت |
| **دوره زمانی (Period)** | بازه‌های زمانی برای تفکیک داده‌ها و گزارش‌ها |
| **کاربر (User)** | با نقش‌های superadmin, admin, user و سطوح سازمانی |
| **ساختار سازمانی (Org Structure)** | یگان‌های اصلی و جزء با سطوح سه‌گانه |

## ۴. فرآیندهای کلیدی (Business Flows)

### ۴.۱. مدیریت درختواره‌ها (Knowledge Tree Management)

- کاربر می‌تواند **درختواره مورد نیاز (Required)** و **درختواره تولیدشده (Produced)** ایجاد کند.
- هر درختواره شامل گره‌هایی با سطوح مشخص است.
- گره‌های برگ (`L`) در درختواره مورد نیاز، به **قالب‌ها** متصل می‌شوند.
- گره‌های برگ در درختواره تولیدشده، به **نمونه‌های قالب** متصل می‌شوند.

### ۴.۲. تحلیل شکاف (Gap Analysis)

- سیستم با مقایسه دو درختواره، **گپ‌های دانشی** را شناسایی می‌کند.
- وضعیت گپ‌ها: `open` (باز)، `partially_filled` (نیمه‌پر)، `filled` (پر شده).
- تحلیل بر اساس **تطابق عنوان، قالب‌ها و نمونه‌ها** انجام می‌شود.
- خروجی تحلیل به صورت **جدول، گراف و گزارش اکسل** قابل مشاهده است.

### ۴.۳. تولید درختواره پژوهشی (Research Tree)

- از گپ‌های باز، به‌صورت خودکار **درختواره پژوهشی** تولید می‌شود.
- هر گپ باز به یک **آیتم پژوهشی** تبدیل می‌شود.
- آیتم‌های پژوهشی دارای **۹ ستون تحلیلی** (اهمیت، اولویت، بازه زمانی، تأثیر رزمی و ...) هستند.

### ۴.۴. نظام مسائل (Issue System)

- هر آیتم پژوهشی می‌تواند به یک **مسئله** تبدیل شود.
- هر مسئله شامل **۴۰+ فیلد** است:
  - اطلاعات کلی (عنوان، حوزه، اولویت، سطح محرمانگی)
  - اطلاعات پروژه‌ای (نوع پژوهش، نوع دانش، رویدادها)
  - اطلاعات مالی (بودجه مورد نیاز، مصوب، تخصیص‌یافته)
  - اطلاعات اجرایی (اقدامات، گلوگاه‌ها، دستورات)
  - تیم حل مسئله (با امکان ثبت اعضا)
  - بیانیه نیاز (با فایل پیوست)
  - اطلاعات قرارداد (شماره، مجری، همکاران، مبلغ)
  - مراحل پیشرفت (۲۰%، ۵۰%، ۱۰۰%)
  - کاربست نتایج

### ۴.۵. خروجی‌ها (Outputs)

- خروجی **اکسل** در ۶ شیت جداگانه:
  ۱. اطلاعات کلی  
  ۲. درختواره  
  ۳. شکاف‌ها  
  ۴. پژوهش  
  ۵. مسائل  
  ۶. دارایی‌ها  
- خروجی **گراف** با استفاده از D3.js و SVG
- امکان **پیش‌نمایش گراف** قبل از دانلود

## ۶. امنیت و دسترسی‌ها

- احراز هویت با **JWT** و ذخیره توکن در localStorage
- قفل خودکار صفحه پس از مدت زمان مشخص (قابل تنظیم)
- نقش‌های از پیش‌تعریف‌شده:
  - `superadmin`: دسترسی کامل
  - `admin`: دسترسی به مدیریت کاربران و تنظیمات
  - `user`: دسترسی به صفحات دانشی و جستجو
- امکان تعریف **نقش‌های سفارشی** با دسترسی‌های granular
